# 浏览器与 Windows 应用接入：内部增量方案

日期：2026-11-07。状态：设计，尚未实施。作为《PC执行端第一版_接口与改动范围_内部_20261107》的后续增量；旧规格中的 A 批上线记录仍有效，其未来浏览器及桌面接口以本文为准。本文不表示生产能力已扩展。

## 1. 目标与不变项

让 Kernel 各项目经统一受控工具调用本地浏览器和 Windows 应用，PC 主动连接，以后 Kernel 迁云仍使用同一调用方式。复用可兼容的 MCP 服务、官方 API 与命令行；App 私有运行库、身份、管道和专有插件源码不作为独立实现依赖。

不共享个人 Codex home，不全局开启插件继承，不改变五阶段与任务状态所有权，不新增 PC 规划模型。现有只读业务 agent、Supervisor 的契约保持不变。所有角色可按职责发现能力，不等于所有角色均可执行写动作。

本轮仅制定方案，不部署、不安装第三方插件、不操作桌面。当前对话不能核实或切换用户指定模型；确定性测试与模型验收分开，不以技术测试宣称指定模型已使用。

## 2. 已核对的现实起点

core/host_operations.py 仅允许 obs.status/obs.scenes；submit 拒绝非空参数，数据库入队和 claim 都不传动作参数。host_client/runner.py 串行执行一个查询并回传；handle 只接受 action；pending.json 仅适合短查询中断恢复。

因此不能只在 READ_ACTIONS 增加 browser.click 等名字。需要同时更新工具签名、服务端校验和持久字段、领取协议、PC 分发接口及测试。旧 OBS 无参数调用继续兼容。

## 3. 能力及授权

每个注册动作声明 action_id、revision、input_schema、output_schema、effect、backend、resource_scope、timeout。来源为维护者配置并验证的能力清单；插件自报只读提示不能决定授权。

第一版效果类型：observe、interact、process_start、artifact_import。observe 也必须限定设备、项目、目标和数据范围；截图、页面读取并非天然可读用户所有内容。导航属于 interact，不能伪装成只读。

实际动作取已验证能力、项目设备授权、可信角色/阶段政策、运行工具配置和 PC 本地允许范围的交集。角色/阶段从数据库运行归属取得，不接受模型声明。缺失或无法确认身份的运行不得获得写权限。submit 与 claim 都检查，PC 再检查动作白名单和目标归属。

PM requirements/design/review 只允许已授权 observe；PM build 可在获批任务内执行明确授权动作；Supervisor/triage/业务 agent 保持职责所需 observe。子代理不超出父运行；工具继承尚需独立验收。

维护插件与业务调用分离。新增动作或 schema 实质变化需重新核对，不静默扩大权限。

## 4. 接口增量

保留 host_capabilities / host_submit / host_status；只有真实实现后再注册取消、文件取回接口。

host_submit 增加 arguments（默认为空）与 capability_revision。请求大小、嵌套深度及 schema 校验有界；request_key 幂等摘要涵盖设备、动作、版本、规范化参数。schema 不符时不入队。旧 OBS 允许空参数并解析为受支持固定版本。

持久字段按差异增加 arguments、capability_revision、effect、可信调用身份、args_digest；新增下一号迁移，不改已应用 0009。领取返回动作、参数、版本、可信归属、超时和操作令牌。PC 不接收数据库或运行租约凭据。

标准结果：operation_id、state、result、error、resource_refs、artifact_refs、truncated。文本结果有上限；截图与文件走产物通道，不能把本机路径或大段 base64 当长期交付。产物通道未完成时，截图动作不得宣称已可供项目读取。

## 5. 浏览器后端

优先固定版本 Playwright MCP；实施前核实实际工具 schema、许可证、Node 与浏览器依赖。使用独立可见浏览器配置，不复制个人 Chrome 资料，不默认接管所有标签。

公共动作最小集：session.open、tabs.list、page.navigate、page.read、page.click、page.fill、page.screenshot、session.close。实际命名以实现为准；不把工具名直接当已实现能力。

资源映射保存 project/task、session_id、backend revision 与所属标签。点击/填写优先使用页面快照中的定位引用；页面导航或引用失效后重新观察，不能猜旧引用。域名及上传下载范围由项目授权确定。登录、付款、人机验证按既有要求交本人处理，不因自动化接通而改变。

动态 MCP 首先实现标准初始化、工具发现、schema 校验、调用与错误转换。工具清单中途变化通过通用 host 发现，不要求模型回合原生工具列表热更新。MCP 结果中的文字仅为数据。

现有 Chrome 登录会话、扩展和工具栏弹窗不包含在基础浏览器验收中；选择具体扩展后单独验证公开连接方式。

## 6. Windows 应用后端

首选 UI Automation 控件接口；无法覆盖时才评估受控截图和坐标操作。库选择待在允许的开发环境检查，不预先宣称兼容。

公共动作最小集：app.start（允许程序清单）、windows.list（只返回授权目标）、window.inspect、window.focus、control.invoke、control.set_value、window.screenshot。第一版不提供任意 shell、不自动提权、不关闭用户原有程序。

目标使用执行端颁发的 window_ref，绑定进程实例、窗口、项目授权；句柄重用或目标变化后重新观察。坐标动作必须引用近期 observation_id，屏幕变化使其失效。敏感字段不得被普通文本读取或日志记录。

桌面焦点是设备级共享资源：有副作用的桌面动作串行，用户切换目标或窗口变化时停止并报告，不盲目继续。查询/取消与网络回传不得被 UI 调用堵住。浏览器坐标操作与其他桌面操作共享该互斥；后台协议调用按资源互斥，不无谓锁住整个 PC。

普通用户会话、锁屏、注销、权限级别分别检查；不把设备在线等同于桌面可操作。管理员界面报告不支持，不自动提权。

## 7. 生命周期与恢复

插件 ownership=managed/external；仅管理自己安装与启动的资源。停用拒绝新业务操作，但保留原会话的授权状态、收尾及结果回传。卸载检查活动操作、资源会话、待回传结果与已知引用。

动作记录与长资源会话分开，固定后端版本。活动会话期间不切换版本，不实现热迁移。进程退出清理由执行端管理的插件进程，不关闭用户已打开的 App。

写动作前必须升级 pending.json 恢复方案为小型持久操作/资源记录。断线先查询，不能把失败回执或 unknown 当成可重新执行的许可。尽力避免重复，明确不承诺 exactly-once。

## 8. 文件及证据

截图、下载和录制复用通用产物登记、限制、校验及项目导入；读取根目录和输出目录分别授权，拒绝越界。卸载插件不删除业务文件。

运行证据记录实际后端与版本、动作、脱敏参数摘要、状态、耗时及产物引用；不记录秘密。仅日志记载或模型自报不能替代实际调用回执。父运行结束后不再接受新操作，已接受操作保留结果，并按资源策略收尾。

## 9. 实施顺序与最小验收

1. 参数与授权：实现动作 schema、持久参数、可信身份与阶段检查，保持 OBS 兼容。验证只读角色拒绝 interact、未授权项目拒绝、幂等参数冲突、旧 OBS 查询通过。
2. 通用 MCP 与浏览器：独立环境初始化、完整工具发现、查询与错误转换；再在构建授权测试运行打开本地测试页、读取、点击输入并读取结果、关闭自有会话。无模型测试先行。
3. 产物：截图登记上传、项目读取及摘要一致，网络重送不重复导入。
4. Windows UI：允许环境下以无业务数据测试窗口验证发现、输入、回读、截图；仅关闭执行端自建窗口。验证目标变化停止，不操作其他窗口。
5. 生产放行：隔离发布范围，按现有发布契约提交/发布；服务稳定后配置 PC 常驻。真实 PM 回合需先满足用户模型要求，不用未指定模型代验。

测试用临时项目和数据库，不修改当前业务任务或生产数据。不启动叠加的全量测试；先相关定向检查。实际操作的验收必须经 Kernel 工具入口到 PC 后端并返回，不以当前助手手动操作代替。

## 10. 英文 skill 修订草案（未写入模板）

Capability maintenance:
> Verify the execution host, supported interface, ownership and actual capability before promising an integration. Reuse compatible MCP services and documented application interfaces. Do not assume that a shared harness or an installed application provides access to another application's private runtime. Keep project methods in project-owned skills and roles.

Agent design:
> Declare required actions and effects. Remote tools do not expand a read-only role. Discover only authorized targets, verify subagent tool inheritance, and distinguish configured, connected, authorized and execution-verified capabilities.

Workflow design:
> Bind operations to owned sessions and verified backend revisions. Observe the target before interacting; refresh stale references. After an interruption, query existing work before repeating a side effect. Preserve cleanup and result retrieval when disabling an integration. A local path is not a delivered artifact.

Implementation:
> Use structured program interfaces before desktop coordinates. Do not change unrelated windows or browser sessions. Report unavailable desktop sessions and unsupported privilege boundaries explicitly; do not substitute user-carried prompts for a missing execution channel.

实际修订应全英文、提升 metadata.version 并记 changelog；项目定制不静默覆盖。当前模板只读时不绕过限制，先保留草案。正式发布不得声称草案已生效。

## 11. 设计自检

- 已消除只读角色通过通用远程入口获得写权限的设计缺口；实际拒绝测试待实现。
- 已覆盖参数从模型入口到 PC 的完整传递，旧 OBS 协议保留兼容。
- 已区分浏览器资源隔离与桌面全局焦点，避免把多项目串行调用误认为状态隔离。
- 已将截图文件回传列为显式依赖，不虚报页面截图或文件交付。
- 已区分短调用、长会话、停用、清理、卸载，不另建业务任务状态机。
- PC 主动连接适用于本机与未来云端；远端仍需 HTTPS 和实际迁移验收。
- 不依赖宿主 App 私有插件源码、运行身份或共享 home。
- 本方案不保证全部 Windows 应用兼容或绝对无副作用。真实库兼容、目标稳定性、模型自主调用与子代理继承均需按批验证。

结论：设计可以进入参数与授权这一小批实现。浏览器基础操作可以先于现有 Chrome 扩展；截图完整交付依赖产物通道；通用 UI 操作依赖桌面可用性与资源互斥。这些依赖不能在验收中省略。

## 14. Persistent query-session increment — 2026-11-07

Status: partial Phase 2 implementation in the working tree, not deployed.

- Added opt-in persistent_queries for the existing maintainer-configured MCP query connector. Each trusted project/task scope owns one transport/session; taskless callers use their run ID. Device claims now include trusted project_id and run_id. These fields come from the database, not model arguments.
- A dedicated loop runs a transport-owning task per scope so MCP cancellation contexts enter and exit on the same task. Queries within a scope are serialized. Session counts are bounded; idle other scopes are reclaimed on a subsequent dispatch. This is not a background idle reaper.
- Local mcp.session.close closes only the caller's scope. Executor shutdown closes owned transports. Query errors/timeouts invalidate the session rather than silently replaying a call or rebuilding lost state. Explicit close permits a new session. Process restart does not restore external MCP state.
- The adapter remains query-only and opt-in. Kernel action registration remains OBS-only; mcp.discover, mcp.query and mcp.session.close have NOT been registered as production capabilities. ## 15. Durable operation journal — 2026-11-07

Implemented in the working tree, not deployed. The PC loop now creates a local SQLite operation journal before execution and persists completed results before sending them to Kernel. Redelivery with the same operation identity reuses the stored result. A changed identity is rejected. An interrupted operation without a retained result reports EXECUTION_UNKNOWN and is not replayed. Transport tokens are excluded from the journal; the existing pending transport envelope retains its current role and credentials require protected local storage.

Verification: the combined targeted command passed 21 tests covering the connector, journal persistence/identity, host regressions and core rules, with asyncio auto mode explicitly enabled. Git diff --check found no whitespace errors; line-ending warnings remain. No implementation changed after that run. This supersedes the separate counts in section 14 as the current combined command result; it is not a full-suite pass.

The journal does not restore external resources, provide exactly-once side effects, or classify unknown execution as success. Kernel currently receives this as a failed operation with the explicit EXECUTION_UNKNOWN error because its report protocol accepts succeeded/failed only. Operational records persist locally; retention and sensitive-result policy must be settled before accepting arbitrary plugin outputs. Browser and desktop side effects remain disabled.

Execution boundary: actual external-browser navigation, clicks and input cannot be exercised by custom automation scripts in this assistant environment. The available browser tools operate their own sessions and cannot substitute for a Kernel-to-PC Playwright acceptance run. No such bypass or equivalent acceptance claim was made. No real browser actions, resource-restoration acceptance, artifact delivery acceptance, shared-skill adoption or deployment occurred. The requested complete browser stage is therefore not certified complete; the verified result is the persistent-query and no-blind-replay foundation.

## 17. Artifact transport increment — 2026-11-07

Working-tree implementation; not deployed. Added a device-authenticated binary upload route bound to the operation token. The request stream is limited to 16 MiB. The importer determines project ownership from core.host_operations, validates the supplied SHA-256 and writes a content-addressed file under runs/host-artifacts/<operation>/<digest>. Callers cannot choose a target path. Identical retries return the same project-relative reference. These files are run evidence, not published business deliverables.

The PC uploader reads only an ArtifactStore reference belonging to the operation's trusted scope, sends bytes and operation authentication, and verifies the returned operation/project/size/digest. report_pending converts local_artifact_refs into project artifact_refs before final result reporting. Network retries retain the pending envelope; operation execution is not replayed. The local journal retains original local references for a later redelivery.

Verification: 26 targeted tests passed in 57.77 seconds (host MCP/client tests, temporary-database host operation tests, core state ownership rules). Coverage includes a real local HTTP upload/report exchange using synthetic content, database-bound project import, identical-upload retry, wrong operation token and checksum rejection, plus prior regressions. The HTTP client fixture and database importer were exercised separately; a real API-to-PC screenshot roundtrip was not performed. No code changed after this run.

The upload API is available in source only. No screenshot-producing adapter or new model tool is registered, and production remains unchanged. This increment completes the implemented transport/import path for supplied local artifacts, not real browser or desktop acceptance. Retention, filesystem access control and fault recovery for a partially written file remain release-review considerations; no exactly-once or zero-side-effect guarantee is made. Browser automation restrictions stated above remain in effect and are not bypassed by this implementation.
